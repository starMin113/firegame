# Firefighter Rescue MVP：核心玩法方向讨论整理

> 本文整理本轮关于消防灭火小游戏的讨论结论。\
> 当前阶段以**核心体验验证**为主，不把尚未验证的机制当作正式设计方案。

## 1. 当前项目定位

本项目与 BBQ Party 的"限时压力 / 烧焦失败 /
三消"逻辑不同，不应沿用其设计思路。

当前更合适的方向是：

> **以铺设水管为主要交互，以灭火过程作为满足感兑现，并保留轻益智可能性的休闲解压小游戏。**

核心体验关键词：

-   手指连续滑动铺设水管
-   水源与火场形成清晰因果关系
-   通水时有明显反馈
-   喷水"呲呲呲"灭火具有满足感
-   一片混乱、燃烧的区域逐渐被清理干净
-   操作简单，但不意味着完全没有思考

需要特别避免两个极端：

1.  **不要做成高压力资源管理 / 限时策略游戏。**
2.  **也不要过早做成只有喷水特效、缺少可持续玩法的纯视觉解压游戏。**

------------------------------------------------------------------------

## 2. 关于"爽感"的修正

最初讨论曾倾向于把"灭火爽感"放在绝对核心位置，例如：

> 铺管 → 通水 → 喷水 → 大面积火焰熄灭。

这个方向没有错，但不能把"爽感"简单理解为：

> 玩家必须一直喷水、一直处于高潮。

用户提出了一个重要问题：

如果为了维持持续爽感而采用：

> 这里灭掉 → 那里重新燃起来 → 再灭 → 再起火

那么玩家的劳动会被系统不断否定，而且为了连续性强行让火势循环，本质上可能需要推翻现有玩法。

因此当前结论是：

> **灭火是奖励反馈，不一定需要成为全程持续发生的操作。**

更合理的节奏可以是：

> 观察 → 判断 → 操作 → 局面变化 → 灭火反馈 → 新问题 → 最终完成。

也就是说，爽感可以集中在若干节点，而不需要全程处于爆点。

------------------------------------------------------------------------

## 3. 轻益智与解压并不冲突

讨论中参考了《鳄鱼小顽皮爱洗澡》以及停车场出车类休闲游戏。

这些产品说明：

> **解压 / 满足感并不排斥轻度益智。**

玩家完全可以经过一系列简单观察和操作，最终获得一个明显的释放。

因此，本项目可以探索：

> **轻益智负责维持游戏持续性，灭火负责兑现玩家的努力。**

这里的"益智"不应走向复杂计算，而应保持：

-   看一眼基本能理解问题
-   思考时间较短
-   操作方式始终简单
-   解法成功后马上得到视觉和听觉反馈

例如：

-   如何绕开障碍
-   水管从哪里通过
-   先连接哪个区域
-   如何到达喷头
-   某处灭火后开放新的路径

这些都属于轻量问题，而不是硬核策略。

------------------------------------------------------------------------

## 4. 不建议依靠"火不断复燃"制造持续性

当前倾向：

> **一处火被扑灭以后，应当形成明确、最好不可逆的进展。**

例如：

``` text
🔥 燃烧
↓
💦 灭火
↓
💨 白烟
↓
⬛ 焦黑
↓
🌱 / 🌳 / 修复后的建筑
```

随着玩家推进，整个场景应该越来越干净、越来越舒服。

因此游戏连续性更适合来自：

> **一关接一关，以及一关内部多个小目标的连续解决。**

而不是让同一个火场永远烧不完。

------------------------------------------------------------------------

## 5. 单关可能的节奏结构

当前比较值得验证的是 30～90 秒左右的小关卡。

一个关卡可以包含多个小阶段：

``` text
观察 / 铺管
     ↓
第一处通水
     ↓
小范围灭火（小爽点）
     ↓
出现新路径 / 新目标
     ↓
继续铺设
     ↓
第二处灭火（中爽点）
     ↓
最后连接
     ↓
大面积灭火
     ↓
CLEAR（大爽点）
```

这样能够形成：

> **思考 → 操作 → 兑现 → 再思考 → 再操作 → 更大的兑现**

而不是：

> 一根管 → 一次喷水 → 立即结束

也不是：

> 无限起火 → 无限灭火。

------------------------------------------------------------------------

## 6. 美术资源有限时的处理原则

作为独立开发项目，不应该把项目成败押在高规格美术表现上。

更现实的公式是：

> **低成本表现 + 强交互反馈 + 明显状态变化 = 足够的满足感**

高成本、当前不值得投入的内容：

-   写实动态火焰
-   真实流体模拟
-   高级水体效果
-   大量复杂场景资产
-   复杂消防模拟

相对低成本但高收益的反馈：

-   连续铺管时的吸附与节奏
-   水沿水管传播
-   喷水粒子
-   火焰缩小
-   蒸汽 / 白烟
-   喷水声
-   水接触火焰的"呲------"声
-   震动
-   焦黑区域恢复为正常环境
-   大片区域从燃烧状态变为干净状态

核心原则：

> **美术负责放大爽感，而不是负责制造爽感。**

如果只有换上高级美术以后才觉得好玩，反而说明核心交互本身可能存在问题。

------------------------------------------------------------------------

## 7. 场景：室外还是室内

目前不应该过早锁死室外或室内。

### 室外优势

-   适合连续铺较长水管
-   空间宽松
-   容易表现大片灭火
-   容易产生场景恢复的视觉反差
-   美术资产可以相对简单
-   更容易体现规模感

适合：

-   森林
-   露营地
-   农场
-   郊区
-   加油站
-   工地
-   港口
-   小镇街区

### 室内优势

当"轻益智"重新进入设计以后，室内也有明显价值：

-   墙体天然形成路线限制
-   房间可以制造空间结构
-   门、货架、家具等可以形成简单障碍
-   更容易产生路径选择

风险是：

> 室内过度复杂以后，游戏可能变成纯路径规划 / 迷宫 Puzzle。

### 当前建议

暂时不要决定。

后续可以分别制作：

-   A：室外森林测试关
-   B：室内仓库测试关

使用同样的临时素材和机制，比较：

1.  哪个铺管更自然？
2.  哪个更容易产生适度思考？
3.  哪个灭火完成以后更有"处理干净了"的感觉？

最终也可能采用：

> **室外负责规模与释放，室内负责路线变化。**

------------------------------------------------------------------------

## 8. 关于"水管网络"

讨论中曾提出"水管网络"，但这个概念目前不是既定核心。

所谓水管网络，只是：

> 玩家铺过的管子保留下来，并且可以从已有水管继续延伸或分叉。

例如：

``` text
                  💦 火点 B
                 /
水源 🌊 ━━━━━━━━┫
                 \
                  💦 火点 C
```

这样最终地图上会留下玩家自己建立的供水结构。

它可能带来：

-   建造成就感
-   多目标连续灭火
-   分叉玩法
-   多喷头同时工作的最终反馈

但它也可能让游戏明显向：

> **管线规划游戏**

偏移。

因此当前处理方式：

> **把"水管网络 / 分叉"保留为候选机制，不默认它就是核心。**

首先验证最基础的一根水管是否成立。

------------------------------------------------------------------------

## 9. 当前最重要的问题

现在不应该继续讨论：

-   第 50 关怎么玩
-   第 100 关怎么玩
-   有多少种消防设备
-   成长系统
-   经济系统
-   商业化
-   大量场景主题

当前必须先回答：

> **"铺水管 → 通水 → 灭火"这个最小动作循环，本身有没有意思？**

然后再回答第二个问题：

> **加入一点轻益智以后，是增强了灭火的满足感，还是阻碍了它？**

这两个问题决定整个项目未来的方向。

------------------------------------------------------------------------

# 10. 下一步开发任务：核心体验测试关

下一步不做正式第一关，而制作一个 **30～60 秒核心体验测试场景**。

只需要：

``` text
水源
 ↓
手指连续铺设水管
 ↓
绕过一个简单障碍
 ↓
连接火场
 ↓
通水
 ↓
喷水
 ↓
火逐渐熄灭
 ↓
完成
```

示意：

``` text
┌─────────────────┐
│ 🌲 🔥🔥🔥 🌲    │
│ 🌲 🔥🔥🔥 🌲    │
│                 │
│    ■■■          │
│    ■■■          │
│                 │
│ 💧              │
└─────────────────┘
```

------------------------------------------------------------------------

## 11. P0：铺管手感

这是当前最高优先级。

要求：

-   手指划过连续格子即可铺管
-   不要求玩家精准点击
-   快速滑动也能够正确连续铺设
-   自动处理转弯
-   水管视觉连接自然
-   错误路径容易撤销
-   撤销不打断节奏

目标体验：

> **唰唰唰唰------水管顺着手指快速铺过去。**

而不是：

> "为什么这一格没放上？"

------------------------------------------------------------------------

## 12. P0：通水反馈

水管到达目标以后，不要直接让火消失。

需要让玩家看到：

``` text
水源启动

💧 → ▬ → ▬ → ▬ → ▬ → 🚿

约 0.3～0.8 秒

🚿 💦💦💦 → 🔥🔥🔥
```

水沿玩家刚刚铺设的路线传播，可以让：

> **铺管行为与灭火结果形成明显因果关系。**

这个过程可以非常廉价，不需要真实流体模拟。

------------------------------------------------------------------------

## 13. P0：灭火反馈

第一版不要追求高规格美术。

最简单的火焰变化即可：

``` text
🔥 大
↓
🔥 中 + 白烟
↓
🔥 小 + 白烟
↓
💨
↓
熄灭
```

同时加入：

-   持续喷水声音
-   水接触火焰的"呲------"声
-   简单白烟 / 蒸汽粒子
-   必要时轻微震动
-   灭火后的明显环境变化

目标不是证明"美术很强"。

目标是验证：

> **廉价反馈组合以后，这个过程是否依然舒服。**

------------------------------------------------------------------------

# 14. 第二个实验：加入轻益智

基础版本完成以后，不提高美术，只增加一个简单障碍。

制作两个版本：

### A 版：纯解压

几乎不需要思考。

``` text
水源 → 铺管 → 火场 → 灭火
```

### B 版：轻益智

增加一个非常简单的路线问题：

``` text
             🔥🔥🔥
                ↑

       ■■■■■■■
       ■     ■
💧━━━━?      ■
       ■     ■
       ■■■ ■■■
```

玩家需要观察几秒，然后找到路线。

------------------------------------------------------------------------

## 15. 测试重点

自己连续体验，同时最好找 3～5 个不了解设计意图的人试玩。

不要主要问：

> "你觉得好玩吗？"

重点观察：

-   玩家会不会自然地快速滑动铺管？
-   是否需要解释操作？
-   第一次通水时会不会停下来观看？
-   喷水灭火是否有明显满足感？
-   灭完以后是否愿意马上进入下一关？
-   A 版是否很快产生重复感？
-   B 版的思考是在增加期待，还是阻碍灭火？
-   连续玩 3 关以后是否已经觉得重复？

测试结果将帮助决定：

> **游戏最终更偏纯解压操作，还是偏"轻益智 → 灭火兑现"。**

------------------------------------------------------------------------

# 16. 当前开发优先级

## P0 --- 必须先验证

1.  连续铺管手感
2.  通水反馈
3.  喷水 / 灭火反馈

## P1 --- 核心方向验证

4.  一个简单障碍
5.  A/B 比较"纯解压"和"轻益智"
6.  验证 30～60 秒单关节奏

## P2 --- P0/P1 成立后再考虑

7.  分叉
8.  喷头
9.  水管保留 / 水管网络
10. 多个火点
11. 室内 / 室外主题比较
12. 单关多个阶段

## P3 --- 暂缓

-   复杂火势蔓延
-   水量资源管理
-   水压模拟
-   限时失败
-   复杂消防设备
-   消防员 AI
-   成长系统
-   经济系统
-   大量关卡
-   大规模正式美术制作

------------------------------------------------------------------------

# 17. 当前阶段的一句话结论

> **先用最低成本，把"一根水管、一处水源、一片火"的体验做舒服；再用一个简单障碍验证轻益智是否能让最终灭火更有满足感。**

目前不需要证明游戏能做 100 关。

首先需要证明：

> **玩家愿不愿意接第二根水管、灭第二片火。**

这才是当前 MVP 最重要的验证目标。
