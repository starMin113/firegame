# Unity 首个可玩切片

日期：2026-11-03。状态：技术建议与任务基线，尚未完成实现。

## 要验证的结果

第一关选用公路汽车火灾：场景结构简单，可以把注意力放在铺拆、开关、水流与灭火反馈。沿用 Web 第一关作为规则参照，具体数值经验证后调整，不直接宣称它已是最终教学关。

玩家能观察水源和火点，拖动铺管或拆管，开启水源，观看水流传播与火点熄灭，完成关卡；可以停水、撤销和重置。第一关必须有简化场景与基础声音反馈，正式成套资产暂不生产。

## 美术与布局提案

建议先试清晰、明亮、形体简洁的 2D 插画风：场景适度降饱和，橙红火焰、蓝色通水状态形成重点。水源、阀门与灭火器同时用轮廓、图标和状态区分，不只靠颜色。

格子是布局与交互规则，可在准备铺设时辅助显示；汽车、建筑、水源应构成真实可辨的事故现场。避免直接把 Web 棋盘当最终画面，也不采用妨碍手机识别的写实小细节。

先用同一关制作手机竖屏和横屏布局对比，检查有效场景面积、格子触控尺寸、资源栏和手指遮挡。选定基准分辨率后，再确定安全区、自适应规则和资源图标尺寸。此提案没有替用户锁定风格或屏幕方向。

样稿需展示：未通水、通水中、火点被扑灭三个状态；UI 至少包含剩余水量、水管、灭火器、撤销、重置与水源开关。撤销与重置位置固定，水源开关贴近对应设施。

## 技术方案

在现有 Unity 2022.3 / URP 2D 上实现。场景用 SpriteRenderer、必要的粒子与轻量动画，UI 优先 uGUI + TextMeshPro。暂不切换引擎版本、不引入额外框架、DI 容器、ECS、寻址资源系统或联网后端。

建议代码结构如下；实际创建前检查现有文件与依赖：

| 模块 | 职责 | 边界 |
| --- | --- | --- |
| Core | 网格、资源、管网连通、火点、揭露、有效操作和胜利状态 | 纯 C# 规则，不读取 Transform、UI 或真实时间 |
| Levels | 静态关卡配置与验证 | ScriptableObject 作为编辑入口，运行时复制状态；不修改原始资产 |
| Application | 操作顺序、传播阶段、快照历史、重置和关卡生命周期 | 协调规则与表现，不由动画脚本自行扣资源 |
| Presentation | 场景映射、分层、UI、水火动画与声音 | 订阅状态或结果；表现完成不成为资源真实性的依据 |
| Input | 屏幕到网格映射、鼠标与单指拖动、输入取消 | 共用手势规则，UI 命中不穿透到地图 |
| Tests | 规则和状态恢复回归 | 关注玩家可见行为与不变量，不镜像实现细节 |

关卡包含稳定 ID、尺寸、障碍、水源及容量、火点需求、初始可见性、揭露关联和工具预算。首先做 Inspector 可配置与基础校验；有实际批量制作瓶颈后再做专用编辑器。

水传播采用逻辑事件序列，表现按节奏播放；每个火点真正完成灭火时统一提交一次扣水与揭露。停水取消尚未执行的事件；撤销恢复开闸前快照，并取消旧表现回调。具体并发顺序以现有 Web 规则和回归用例核对，避免静默改玩法。

快照必须包含水源剩余量、管线、火点、可见性与工具；静态关卡不重复保存。一次拖动一次历史记录；取消手势恢复拖动前状态。第一版不做跨会话的中途关卡存档；后续按需求定义版本和迁移。

输入规则保持已确认约定：前一格有管且当前有管则拆当前格；前一格有管且当前无管则铺设；连续划拆依据采样到的占用状态，避免前一格被拆后中断。重复经过不能反复切换；通水期间不编辑管网。起点、快速跨格与抬手行为以原型为依据编写明确用例。

表现分层独立处理地形、设施、管道、水流、火烟、迷雾和交互提示；同一格信息不因铺拆被覆盖或丢失。隐藏资源不可提前被输入命中或 UI 暴露，已知线索可单独显示。

持续执行机制优先使用按需更新。动画、传播计时和粒子在活动时运行；不为每格添加常驻 Update。实际实现前列出持续执行点和预计实例范围，实现后报告测量状态。

## 第一关验收

- 资源不足不会出现负数、重复扣除或无法解释的部分操作。
- 水源开关清晰；水管通水前后不同；水到达火点才触发灭火，无需点击火堆。
- 一次拖动只撤销一次；快速拖动不跳格、不误穿障碍，UI 操作不铺管。
- 停水、撤销、重置后没有旧动画继续修改新状态。
- 灭火、揭露及撤销均完整恢复，迷雾、火烟和管道同格时可见性正确。
- 建议有效解和至少一种错误尝试已实际运行；零错误操作也能完成教学。
- 在选定屏幕和实际设备上检查触控、安全区、文字、声音和清场反馈。
- 编译及规则测试通过，Console 无阻断错误；性能报告明确设备和测量方式，未测项不写成合格。

## 扩五关前的决策

用户完成第一关试玩后，记录操作问题和清场感受。若体验未达到预期，先定位是输入、信息、视觉声音还是决策问题，再决定迭代；不自动归因于“美术还不够”。通过后依次迁移其余四关，按每关的核心命题验证，不以凑齐数量代替验证。
